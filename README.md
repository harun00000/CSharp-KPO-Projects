# ПОС

Консольное приложение «Преподавательская Оценка Студентов»

Программа позволяет добавлять студентов и критерии оценивания, выставлять и изменять оценки, рассчитывать итоговый балл и экспортировать результат

## Запуск

```bash
dotnet build Pos.sln
dotnet run --project Pos.Console
```

Для запуска тестов:

```bash
dotnet test Pos.sln
```

### После запуска доступны команды:

- `1` - добавить студента;
- `2` - показать студентов;
- `3` - добавить критерий;
- `4` - показать критерии;
- `5` - выставить оценку;
- `6` - показать оценки;
- `7` - посчитать итоговый балл;
- `8` - исправить оценку;
- `9` - отменить оценку;
- `10` - экспортировать итог;
- `0` - выйти из программы

Итог экспортируется в файл `final_result.csv`

## DDD

### Ubiquitous Language

Термины предметной области:

- `Student` - студент;
- `Criterion` - критерий оценивания;
- `Evaluation` - выставленная оценка;
- `Score` - балл;
- `Rubric` - рубрикатор;
- `FinalScoreService` - расчёт итогового балла

### Entity и Value Object

`Student`, `Criterion` и `Evaluation` - Entity, потому что для них важен `Id`.

`Score` - Value Object: для него важно само значение балла, а не идентификатор

### Инварианты

- балл не может быть отрицательным;
- балл не может быть выше максимального балла критерия;
- оценка может быть создана только для критерия, который находится в `Rubric`;
- в `Rubric` не может быть двух критериев с одинаковым `Id`

При изменении оценки она создаётся заново (через `EvaluationFactory`), поэтому те же ограничения продолжают проверяться

### Aggregate boundaries

`Rubric` управляет набором критериев оценивания

`Student` хранится отдельно, а `Evaluation` связывает студента, критерий и выставленный балл

### Repository

`IStudentRepository` и `IEvaluationRepository` - порты для работы с хранилищем

`InMemoryStudentRepository` и `InMemoryEvaluationRepository` - их реализации в `Infrastructure`

### Domain Service

`FinalScoreService` - Domain Service, потому что расчёт итогового балла зависит не от одной сущности, а от студента, его оценок и рубрикатора

## Architecture

В проекте используется архитектура `Ports & Adapters`

Проект разделён на слои:

- `Pos.Domain` - Entity, Value Object, инварианты, фабрика и Domain Service;
- `Pos.Application` - сценарии работы со студентами, критериями, оценками и итогом;
- `Pos.Infrastructure` - реализации Repository и экспорт результата в csv;
- `Pos.Console` - консольный интерфейс и DI;
- `Pos.Tests` - юнит-тесты.

Зависимости:

```text
Pos.Console
|-> Pos.Application
|-> Pos.Infrastructure
--> Pos.Domain

Pos.Infrastructure
|-> Pos.Application
--> Pos.Domain

Pos.Application
--> Pos.Domain
```

Repository-интерфейсы выступают портами, а `InMemoryStudentRepository` и `InMemoryEvaluationRepository` - адаптерами

Для экспорта используется порт `IResultExporter`, а его реализация `CsvResultExporter` находится в `Infrastructure`

`Pos.Domain` не зависит от консоли, файлов и конкретного способа хранения данных

DI собирается в `Program.cs` (в `Pos.Console`)

## GoF

### Factory

`EvaluationFactory` создаёт `Evaluation` и проверяет, что оценка корректна

Она не позволяет создать оценку для критерия вне `Rubric` или поставить балл выше максимального

### Facade

`PosFacade` предоставляет консоли одну точку доступа к основным сценариям приложения

Консоли не нужно напрямую работать с `StudentService`, `RubricService`, `EvaluationService` и `ResultService`

### Strategy

`IFinalScoreStrategy` задаёт общее правило расчёта итогового балла

`WeightedFinalScoreStrategy` содержит текущую реализацию расчёта с учётом весов критериев

(если правило расчёта изменится, можно добавить другую реализацию `IFinalScoreStrategy`, не изменяя `FinalScoreService`)

## Тестирование

Тесты находятся в `Pos.Tests`

Они проверяют основные инварианты и работу доменной логики, в том числе:

- невозможность создать отрицательный балл;
- невозможность поставить балл выше максимума критерия;
- невозможность создать оценку по критерию вне `Rubric`;
- невозможность добавить одинаковые критерии;
- проверку данных студента;
- расчёт итогового балла;
- расчёт итогового балла с весами;
- изменение оценки;
- удаление оценки

## Использование ИИ

ИИ использовался как вспомогательный инструмент для написания части кода, юнит-тестов и проверки кода
